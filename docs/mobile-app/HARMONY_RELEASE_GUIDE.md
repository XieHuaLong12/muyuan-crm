# LVANJUBOS · HarmonyOS 版从零到全员使用

> 写给第一次发布 App 的人。按顺序做，每一步都写了在哪里点、填什么。
> 我们是**企业内部分发**，不在华为应用市场公开上架。华为开发者后台里「分发 → 应用上架」那一组（软件包管理、版本信息、准备提交、价格与销售范围）**现在都不用碰**，也不要点「提交审核」。

## 总览：三个阶段

| 阶段 | 目的 | 怎么装到手机 | 需要什么 |
| --- | --- | --- | --- |
| ① 开发调试 | 你自己的一台手机上跑起来，确认能用 | 数据线连电脑，DevEco Studio 直接装 | DevEco Studio、华为账号（自动签名） |
| ② 小范围试用 | 3–5 位同事试用一两周 | 华为后台「应用测试」发邀请，同事在手机上点链接安装 | 发布证书 + Profile、打包好的 `.app`、同事的华为账号 |
| ③ 全员正式使用 | 公司手机都装上，长期使用、能更新 | 企业内部应用发布：安装包放在公司服务器，员工下载安装 | 华为「企业内部应用」发布资格、组织内部发布证书与 Profile |

现在只需要做 ①。① 跑通、问题改完后再做 ②；③ 需要先向华为申请资格，可以和 ②、③ 之前的工作同时进行。

## ① 开发调试：在你的手机上跑起来（约 1 小时）

### 1. 安装 DevEco Studio（电脑上）

1. 打开 <https://developer.huawei.com/consumer/cn/deveco-studio/>，下载 **DevEco Studio 26**（带 HarmonyOS 7 SDK）的 **macOS** 版本：苹果芯片的 Mac 选 ARM 版，Intel 芯片选 x86 版。
2. 安装后第一次打开，按向导下载 SDK，全部用默认选项。

### 2. 拿到代码并打开

1. 代码在仓库 `XieHuaLong12/muyuan-crm` 的分支 `claude/lvanju-bos-mobile-ui-1rdaf6`，目录 `mobile/harmony`。可以用 GitHub Desktop 克隆后切到这个分支，或在 GitHub 网页上切到这个分支后「Code → Download ZIP」解压。
2. DevEco Studio →「Open」→ 选择 `mobile/harmony` 文件夹（注意是这个子文件夹，不是整个仓库）。
3. 右下角会自动同步。如果弹出「升级 modelVersion」「设置 targetSdkVersion」之类的提示，点同意，目标版本选 HarmonyOS 7。

### 3. 自动签名

1. 菜单「File → Project Structure」→ 左侧「Project」→ 上方「Signing Configs」。
2. 勾选「Automatically generate signature」，点「Sign In」，用**公司华为开发者账号**登录（就是你创建 LVANJUBOS 的那个账号）。
3. 看到签名信息自动填好、包名显示 `online.avenlee.bos`，点「OK」。

自动签名只用于开发调试：装在已连接的手机上，不能发给别人。

### 4. 手机打开开发者模式

1. 手机：「设置 → 关于本机」，连续点「软件版本」7 次，输入锁屏密码，提示已进入开发者模式。
2. 「设置 → 系统 → 开发者选项」，打开「USB 调试」。
3. 用数据线连电脑，手机弹出「允许 USB 调试」时选「允许」。

### 5. 运行

1. DevEco Studio 顶部设备下拉框里选你的手机，点绿色三角「Run」。
2. 第一次编译会花几分钟。**如果编译报错**：把下方「Build」窗口里的红色报错整段复制给我，我来改代码，你重新拉取后再运行。
3. 装好后手机上出现 LVANJUBOS，用你的 BOS 账号登录。

### 6. 按这个顺序试一遍

- 登录 → 工作台的数字和电脑端「跟进队列」一致
- 客户：切换队列、搜索 → 点进客户 → 拨号、写跟进（电脑端能看到这条跟进）
- 订单列表与详情 → 消息点开进入客户
- 退出登录，再打开 App 要求重新登录

> 测试站（例如 `test.avenlee.online`）搭好之前，App 连接的是正式站：「写跟进」会写进真实客户记录，测试时选自己负责的客户，写清楚「测试」。

## ② 小范围试用：邀请测试（约半天，加华为审核约 3 小时）

### 1. 生成密钥和证书请求（电脑上，DevEco Studio）

1. 菜单「Build → Generate Key and CSR」。
2. 「Key store file」点「New」新建一个密钥库，保存为 `lvanjubos-release.p12`，设置密码；Alias 填 `lvanjubos`，再设一个 Key 密码。
3. 下一步生成 `lvanjubos.csr`。
4. **立刻备份**：`.p12` 文件、两个密码、Alias，存到公司密码管理器或加密 U 盘，至少两处。**丢了就再也不能给已安装的 App 发更新**。这些文件**不要**放进代码仓库或发到群里。

### 2. 在华为后台申请发布证书和 Profile

1. 华为开发者后台 →「证书、APP ID 和 Profile」（在顶部「开发者管理」或「应用管理」下，以页面为准）→「证书」→「新增证书」：类型选**发布证书**，上传刚才的 `.csr`，下载得到 `.cer`。
2. 同一页面切到「Profile」→「添加」：应用选 **LVANJUBOS**；类型选**发布**；证书选刚才的发布证书 → 下载得到 `.p7b`。
3. `.cer`、`.p7b` 和 `.p12` 放在一起备份。

### 3. 用发布证书打包

1. DevEco Studio：「File → Project Structure → Signing Configs」，**取消**「Automatically generate signature」，依次选择：Store file（`.p12`）、Store password、Key alias（`lvanjubos`）、Key password、Profile file（`.p7b`）、Certpath file（`.cer`），点「OK」。
2. 右上角构建模式选 **release**。
3. 菜单「Build → Build Hap(s)/APP(s) → Build APP(s)」，完成后在 `mobile/harmony/build/outputs/default/` 下找到以 `.app` 结尾的文件。

### 4. 上传并邀请同事

1. 华为后台 → LVANJUBOS →「应用测试 → 测试版本列表」→ 创建测试版本，类型选**邀请测试**。
2. 上传上一步的 `.app`，等「合法性」检测通过；「上架自检」可以跑一下，看有没有兼容性问题。
3. 填写测试说明（可以用 `mobile/harmony/store/app-info.md` 里的文字），提交，等华为审核。
4. 「测试用户」→ 添加同事的**华为账号**（手机号或邮箱）→ 发送邀请。同事在手机上打开邀请，按提示安装。

审核时需要登录账号：在 BOS 里新建一个**审核专用的销售账号**，不分配任何客户。审核人员能登录、能看到每个页面，但看不到任何真实客户。把这个账号和密码填进测试说明，审核通过后在 BOS 里停用它。

另一种方式是**内部测试**：后台注册同事手机的设备 ID（UDID），每个账号最多 100 台，每个版本 90 天有效，不需要华为审核，但要自己搭一个下载页。公司手机不多时，邀请测试更省事。

## ③ 全员正式使用：企业内部应用发布（长期）

用华为提供的**组织内部发布证书和 Profile** 打包，把安装包放在公司服务器（`avenlee.online`）上，员工直接下载安装，不经过应用市场。员工第一次安装后，要在手机「设置 → 系统 → 企业设备和应用管理 → 企业应用管理」里找到 LVANJUBOS，点「允许」。

要做的事：

1. 向华为申请企业内部应用发布资格（在开发者后台或联系华为开发者支持，提供营业执照等企业资料）。资格条件和申请入口以华为当期规则为准。
2. 资格下来后，申请「组织内部」类型的发布证书和 Profile，按 ② 的方法打包。
3. 我在 BOS 上加一个登录后才能访问的下载页，以及 App 内的「检查更新」（方案见 NATIVE_PLAN §5.1、§6.1、S11）。

## 已经准备好的资料（`mobile/harmony/store/`）

| 文件 | 用途 |
| --- | --- |
| `app-info.md` | 应用简介、详细介绍、分类、测试说明、审核账号说明，复制粘贴即可 |
| `privacy-policy.html` | 隐私政策草稿（写了 App 实际收集和使用的数据）。填好公司全称和联系邮箱后，放到 `avenlee.online` 上得到一个公开网址 |
| `icon-216.png`、`icon-1024.png` | 后台要求上传应用图标时用（临时图标：品牌绿底 + 房屋窗格标志，拿到 Logo 矢量源文件后替换） |

**截图**：后台要求截图时，用 ① 装好的 App 在手机上直接截（工作台、客户、客户详情、订单，各一张），不要用原型图，原型里有些功能 App 还没有。

## 以后每次发新版本

1. 我改好代码、推送；你在 DevEco Studio 里拉取最新代码。
2. 把 `AppScope/app.json5` 里的 `versionCode` 加大（例如 1000000 → 1000001），`versionName` 改成新版本号（例如 1.0.1）。版本号我会在提交里一起改好。
3. 用**同一套**发布证书打包（release 模式），按 ② 或 ③ 的方式发出去。
