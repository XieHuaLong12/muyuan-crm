## 2. 设计一致性

| 项目 | 规则 | 状态 |
| --- | --- | --- |
| 颜色 | 组件只引用 `tokens.css` 变量；浅色 / 深色同一套 token | ✅ |
| 品牌色用途 | 只用于主操作、选中、当前页签、AI 与品牌区块 | ✅ |
| 状态色 | 红 = 逾期 / 异常 / 未读；橙 = 即将到期 / 待处理 / 规划；绿 = 完成；蓝 = 进行中 | ✅ |
| 字号 | 8 档，最小 12 | ✅ |
| 触控尺寸 | 可点元素 ≥ 44，主要按钮 48 | ✅ |
| 顶栏 | 根页大标题滚动收起；详情页返回 + 标题 + ≤2 个图标 | ✅ |
| 底部主操作 | 详情 / 表单页固定在底部，主按钮在右 | ✅ |
| 二次确认 | 仅不可逆或影响他人的操作；可逆操作用撤销 | ✅ |
| 数字 | 币种符号 + 千分位；概览用「万」；列内等宽数字；多币种不折算并注明 | ✅ |
| 诚信标注 | 示例数据「MOCK」、AI「建议 · 需人工确认」、新能力「规划 / 新增通知」 | ✅ |

## 4. 原型的边界（不代表最终实现）

- 全部为前端模拟：没有调用 BOS 接口，刷新页面后数据恢复（控制台可「重置示例数据」）。
- 时间固定在 2026-11-10 10:24，用于让「逾期 / 即将到期」等状态稳定可演示。
- 系统通知、拨号、打开 WhatsApp、分享 PDF 只模拟外观与跳转，不调用系统能力。
- 价格、装柜数量为示例值；真实 App 只显示产品库、报价单中的数据。
- 订单详情「推进状态」在原型中会联动付款 / 生产字段，真实规则以 `services/order-service.ts` 为准。
- 屏幕阅读器只做了基础标注（按钮名称、角标、进度条），完整无障碍测试在原生阶段进行。
