# 管理与销售工作空间

## 本次需求与影响分析

2. BOS 边界：影响管理工作空间、Sales OS 和 Task/Reminder；不改变广告归因、AI 发送规则、产品定价、公司目标与现有成交额口径。

4. 数据：仅增量迁移 `20261006090000_sales_role_workspace`。User 新增 isActive/sessionVersion；Customer 新增 assignedAt/firstContactDueAt/firstContactAt/firstContactBy；Deal 新增 nullable salespersonId；Setting 新增首联期限默认 24 小时；新增个人月目标、客户分配历史和账号审计表。既有账号默认启用，旧联系和成交时间不回填猜测。
5. API：维持 `{success,data}`。管理 API 拒绝销售；新增 sales-team performance/focus/accounts/targets/policy。个人业绩按登录销售强制过滤，忽略客户端传入的其他负责人。
6. UI：两套角色导航、品牌首页与顶部入口；管理界面有团队目标和账号；销售有新线索清单、今日跟进和我的业绩。沿用 BOS 原语与 token。
7. 实施与验证：先导航/守卫，再任务与会话隔离，再首联和人员业绩。迁移、并发权限、首联生命周期、旧会话撤销在隔离 MySQL 验证；构建和页面检查同样使用本机测试库。生产数据库不用于测试。

## 角色与入口

管理员首页 `/command-center`：团队经营、销售团队、增长、广告分析、全量客户与看板、销售沟通监督、订单、财务、团队任务、系统设置。

销售首页 `/sales`：简洁的待跟进客户清单、我的客户、我的看板、产品与报价、我的订单、我的任务、我的业绩。销售不提供聊天工作台。`/today` 对销售返回待跟进清单。

直接访问管理页面会回到销售工作台；管理 API 返回 403。客户、会话、订单仍沿用 ownerId 范围；不存在或越权的具体资源返回 404。关联客户的任务以**客户当前负责人**决定访问权，个人无客户任务仅创建者可见。任务搜索条件通过 AND 合并，不覆盖权限 OR。

## 首联与提醒

- 新建客户（人工/通用 Webhook/Meta Lead Webhook）以及管理员转交客户时，记录分配时间和历史。未联系且非终止阶段的客户生成带幂等键的首联任务与 EARLY/OVERDUE 提醒。
- 默认期限为 24 小时，管理员在销售团队页可调为 1–168 小时；仅用于之后的新分配，既有期限不被悄悄改动。
- 首联客户立即进入新线索队列和今日工作；顶部显示待首联数量。首联提醒与任务是站内提醒，未添加外部短信、邮件或手机推送。
- 人工记录跟进、手动登记已联系、完成首联任务、确认报价已发送、WhatsApp 供应商接受出站消息，均记录联系事实并关闭首联任务。系统不会自动给客户发消息。
- 客户已记录联系事实时，转交不重复生成首联；无联系事实的转交关闭旧首联任务并按新分配生成一次任务。自动同步保留 tombstone，不复活已删除任务。
- 历史 CSV、旧客户不猜填首联时间；管理员将未联系客户转交给销售时启动新分配流程。

## 销售业绩口径

- 按公司时区选择自然月，CNY/USD/EUR 分开统计，不混合累计。
- 分配量：该月分配历史中的唯一客户；同一个月重复转给同一人仅计一次。
- 新增/有效/已联系：按询盘日期的该月客户群，负责人为当前客户负责人；历史无 inquiryAt 时回退 createdAt。首联平均时长仅统计已有分配时间与首联时间，且首联不早于分配的真实记录。
- 报价：按发送日期与创建销售统计唯一报价客户，草稿不计为已发报价。
- 成交：按 Deal.dealDate 和 Deal.currency，新成交保存成交时客户销售负责人 salespersonId。之后转交客户不会改写此快照。历史 null 快照暂按当前负责人展示，UI 标记历史归属，不回填猜测。
- 新询盘成交率：该月新询盘群中，该月有成交的客户占比，不用成交笔数除以线索数。
- 首联逾期/待首联为当前运营存量，区别于所选月份的流量指标。
- 个人月目标按 userId/month/currency 唯一，销售只读，管理员设置；未设置显示未设置，零目标完成率显示 `—`。

## 销售账号

销售团队页支持添加销售、修改姓名、停用/启用、重置密码。不能从该页将销售提升为管理员。账号更新使用 sessionVersion 防止陈旧操作，并记审计动作，不存明文密码或密码到审计。

停用立即阻止登录和后续认证请求。账号变更递增 sessionVersion，使旧登录失效；重新启用也不复活旧登录。旧三段 HMAC 会话兼容为版本 0，仅在账号启用且版本仍为 0 时有效。既有 HMAC 密钥和管理员密码不改变。

停用保留客户与历史，管理员决定交接；不能将新客户分配给停用账号，管理员仍可维护该账号已有客户。

## 销售界面修订：沟通监督归管理员（2026-10-06）

1. 需求理解：销售在日常沟通工具联系客户，在 BOS 登记跟进、报价与成交；聊天记录用于管理员监督销售沟通。
2. BOS 边界：销售首页改为客户跟进清单；管理员沟通页保持只读监督，不自动发送消息。现有消息接收与浏览器扩展导入流程保留。
3. 涉及模块：角色导航、SalesOS、客户详情及报价、today/whatsapp 重定向、communication 与同步管理页、WhatsApp 显式 API、统一客户 API、taskInsight、priorityCustomers、identityChain 与 communicationHistory。
4. 数据变化：本次修订没有新表、字段、迁移，也不删除历史消息；既有首联、目标、账号功能保持原有口径。
5. API 变化：消息读取、发送、AI 回复及非签名附件访问需管理员认证；客户详情对销售不包含 whatsappMessages，任务和身份链对销售返回空聊天列表，旧首页摘要不返回消息预览。扩展导入和 Webhook 接收保留既有授权。
6. UI 变化：销售首页以客户、首联期限/下次跟进、记录跟进、档案入口为核心；档案包含报价管理，支持复制报价、打印及登记发送。管理员“销售沟通监督”新增负责人筛选，显示客户当前负责人；不将当前负责人冒充为每条历史消息的实际发送者。
7. 验证与回退：隔离库回归、完整构建、销售页面/API 拒绝聊天访问、管理员按销售筛选和历史翻页、桌面/手机视觉检查。回退本次 UI 时保留此前的账号停用与会话校验。
