# 管理与销售工作空间

## 本次需求与影响分析

1. 需求：管理员管理团队、目标与账号；销售处理自己的新线索、沟通、任务和成交。新客户进入或转交时安排首联，记录真实联系后解除提醒。
2. BOS 边界：影响管理工作空间、Sales OS 和 Task/Reminder；不改变广告归因、AI 发送规则、产品定价、公司目标与现有成交额口径。
3. 模块：`lib/role-workspace.ts`、`lib/session.ts`、`lib/auth.ts`、Sidebar/BOSShell/WorkspaceShell、管理页面与 API、新 `/team` 和 `/sales/performance`、sales-account/sales-team 服务、customer/meta-lead/quotation/whatsapp-message/workflow/task/action-center 服务。
4. 数据：仅增量迁移 `20261006090000_sales_role_workspace`。User 新增 isActive/sessionVersion；Customer 新增 assignedAt/firstContactDueAt/firstContactAt/firstContactBy；Deal 新增 nullable salespersonId；Setting 新增首联期限默认 24 小时；新增个人月目标、客户分配历史和账号审计表。既有账号默认启用，旧联系和成交时间不回填猜测。
5. API：维持 `{success,data}`。管理 API 拒绝销售；新增 sales-team performance/focus/accounts/targets/policy。个人业绩按登录销售强制过滤，忽略客户端传入的其他负责人。
6. UI：两套角色导航、品牌首页与顶部入口；管理界面有团队目标和账号；销售有新线索清单、今日跟进和我的业绩。沿用 BOS 原语与 token。
7. 实施与验证：先导航/守卫，再任务与会话隔离，再首联和人员业绩。迁移、并发权限、首联生命周期、旧会话撤销在隔离 MySQL 验证；构建和页面检查同样使用本机测试库。生产数据库不用于测试。

## 角色与入口

管理员首页 `/command-center`：团队经营、销售团队、增长、广告分析、全量客户与看板、销售沟通监督、订单、财务、团队任务、系统设置。

销售首页 `/sales`：简洁的待跟进客户清单、我的客户、我的看板、产品与报价、我的订单、我的任务、我的业绩。销售不提供聊天工作台。`/today` 对销售返回待跟进清单。

直接访问管理页面会回到销售工作台；管理 API 返回 403。客户、会话、订单仍沿用 ownerId 范围；不存在或越权的具体资源返回 404。关联客户的任务以**客户当前负责人**决定访问权，个人无客户任务仅创建者可见。任务搜索条件通过 AND 合并，不覆盖权限 OR。

## 首联与提醒

- 新建客户（人工/通用 Webhook/Meta Lead Webhook）以及管理员转交客户时，记录分配时间和历史。未联系且非终止阶段的客户生成带幂等键的首联任务与 EARLY/OVERDUE 提醒。
- 默认期限为 24 小时，管理员在销售团队页可调为 1–168 小时；仅用于之后的新分配，既有期限不被悄悄改动。
- 首联客户立即进入新线索队列和今日工作；顶部显示待首联数量。首联提醒与任务是站内提醒，未添加外部短信、邮件或手机推送。
- 人工记录跟进、手动登记已联系、完成首联任务、确认报价已发送、WhatsApp 供应商接受出站消息，均记录联系事实并关闭首联任务。系统不会自动给客户发消息。
- 客户已记录联系事实时，转交不重复生成首联；无联系事实的转交关闭旧首联任务并按新分配生成一次任务。自动同步保留 tombstone，不复活已删除任务。
- 历史 CSV、旧客户不猜填首联时间；管理员将未联系客户转交给销售时启动新分配流程。

## 销售业绩口径

- 按公司时区选择自然月，CNY/USD/EUR 分开统计，不混合累计。
- 分配量：该月分配历史中的唯一客户；同一个月重复转给同一人仅计一次。
- 新增/有效/已联系：按询盘日期的该月客户群，负责人为当前客户负责人；历史无 inquiryAt 时回退 createdAt。首联平均时长仅统计已有分配时间与首联时间，且首联不早于分配的真实记录。
- 报价：按发送日期与创建销售统计唯一报价客户，草稿不计为已发报价。
- 成交：按 Deal.dealDate 和 Deal.currency，新成交保存成交时客户销售负责人 salespersonId。之后转交客户不会改写此快照。历史 null 快照暂按当前负责人展示，UI 标记历史归属，不回填猜测。
- 新询盘成交率：该月新询盘群中，该月有成交的客户占比，不用成交笔数除以线索数。
- 首联逾期/待首联为当前运营存量，区别于所选月份的流量指标。
- 个人月目标按 userId/month/currency 唯一，销售只读，管理员设置；未设置显示未设置，零目标完成率显示 `—`。

## 销售账号

销售团队页支持添加销售、修改姓名、停用/启用、重置密码。不能从该页将销售提升为管理员。账号更新使用 sessionVersion 防止陈旧操作，并记审计动作，不存明文密码或密码到审计。

停用立即阻止登录和后续认证请求。账号变更递增 sessionVersion，使旧登录失效；重新启用也不复活旧登录。旧三段 HMAC 会话兼容为版本 0，仅在账号启用且版本仍为 0 时有效。既有 HMAC 密钥和管理员密码不改变。

停用保留客户与历史，管理员决定交接；不能将新客户分配给停用账号，管理员仍可维护该账号已有客户。

## 销售界面修订：沟通监督归管理员（2026-10-06）

2. BOS 边界：销售首页改为客户跟进清单；管理员沟通页保持只读监督，不自动发送消息。现有消息接收与浏览器扩展导入流程保留。

## 客户分配、更正与性能修订（2026-10-09）

1. 需求：管理员把客户分配给销售是核心流程，此前只能逐个编辑客户资料改负责人；本次补齐分配池、批量分配、更正录入错误，并修复权限、性能与易用性问题。
2. 数据：增量迁移 `20261009024647_assignment_pool_and_corrections`。Customer 新增 `pendingAssignment`（待分配池）、`contactKeysAt`（联系方式规范键已计算）；Setting 新增 `leadAssignMode`（默认 `POOL`）；Task 新增 `assigneeId`。一次性回填：由管理员负责、阶段为新客户且没有任何联系事实的客户进入待分配池，关闭其在管理员名下的首联任务与提醒（此前团队页已把它们计为「仍由管理员负责」）。其他历史数据不改写。

### 分配
- 自动进入的线索（通用线索接口、Meta 表单、Gupshup 入站、未指定负责人的 CSV 导入）按「新线索分配方式」处理：`POOL` 进入待分配池，由最早创建的启用管理员保管，不计首联期限；`ROUND_ROBIN` 分给最久未被分配的启用销售并立即开始首联期限。`WHATSAPP_DEFAULT_OWNER_EMAIL` 指向启用的销售时直接分配给该销售。
- 管理员在客户列表勾选（支持跨页）后「分配 / 转交」，或在客户档案点「分配客户 / 转交」；只修改负责人并写入分配历史与原因，不会用旧表单覆盖资料。CSV 智能导入可直接选择新客户负责人。
- 首联期限从分配给负责人开始计算。团队页显示待分配池数量、分配方式设置、停用账号待交接客户，以及每位销售本月标记无效 / 暂停 / 流失的客户数。
- 客户资料表单携带版本，别人改过后再保存会提示刷新；销售不能修改询盘日期和来源；进入暂不需要 / 已流失 / 无效客户需要填写原因（表单与看板一致），原因写入阶段历史。

### 查重与权限
- 查重只检查本次新增或修改的联系方式，历史重复数据不再阻止编辑其他字段。销售不能「仍然创建」重复客户，会看到联系方式登记在谁的客户名下，以便请管理员核对或转交。
- 管理员可修改、作废成交（作废会取消关联订单，广告回传标记为业务取消，客户回到成交前阶段）；跟进内容可由记录人或管理员更正，管理员可删除；全部写入 IdentityAudit。管理员可取消订单（有成交时等同作废成交）；订单「已完成」只有管理员能设置。
- 单个删除与批量删除一致：已成交客户不能删除。回收站彻底删除会清理联系方式别名、留资、跟进等记录，并解除留资归因与 WhatsApp 联系人的关联；有成交、订单、WhatsApp 沟通、已发报价或已回传广告事件的客户保留并说明原因。
- 所有人可在侧边栏「修改密码」（其他设备登录失效）。管理员可在账号管理中重置 / 停用其他管理员，不能操作自己，且至少保留一个启用的管理员。
- 不关联客户的任务可由管理员指定执行人；客户任务始终由客户当前负责人执行。

### 性能与安全
- 客户列表改为服务端筛选、排序与分页；筛选条件保存在网址中，打开客户再返回保持原状。
- 查重与身份匹配走索引（ContactIdentity / phoneE164 / emailNormalized），只有 `contactKeysAt` 为空的历史客户在内存中比对。跟进、报价、业务事件和不改联系方式的资料编辑只锁单个客户，不再占用全局身份锁；新增成交仍使用全局锁（订单号按天顺序生成）。
- 页面不再每分钟触发全量任务同步：业务事件即时同步对应客户，浏览器最多每 15 分钟请求一次兜底同步。可选定时任务：`curl -X POST -H "x-cron-secret: $META_SYNC_SECRET" https://域名/api/cron/workflows`（建议每小时），同时分批计算历史客户的联系方式规范键。
- 旧版驾驶舱只读取所选周期、上一周期与全年范围内的数据。
- 看板显示全部 13 个阶段，每列独立显示最近需要跟进的 50 位，超出时可跳转到客户列表。
- 登录限流按「邮箱 + 来源地址」与来源地址分别计数，并对单个邮箱设上限，避免别人故意输错把你锁住；登录页不再预填管理员邮箱。登录 Cookie 在 HTTPS 或反向代理 `x-forwarded-proto: https` 下带 Secure，也可设置 `COOKIE_SECURE=true`。
- 所有 API 写操作统一在 `middleware.ts` 校验请求来源（Webhook、定时任务与浏览器扩展同步接口除外）。`/api/cron/meta-sync` 支持 `x-cron-secret` 请求头，旧的 `?secret=` 保留兼容。
- 手动记录的跟进会更新「最近联系」，并让客户移出「待回复」、关闭对应的自动回复任务。
