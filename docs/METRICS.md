# 指标口径

同一个数字在不同页面必须一样。驾驶舱、来源与国家、财务、销售业绩、广告效果、任务页都从 `lib/metrics.ts` 取同一套规则；页面上显示的说明文字在 `lib/metric-notes.ts`。改口径时只改这两个文件，并跑 `tests/metrics-consistency.test.ts`（它在同一时间段比较各页面的数字，必须相等）。

## 时间段

分析页面共用一个时间选择：今天、本周、本月、本季度、本年、自定义（参数 `range`、`startDate`、`endDate`，解析在 `cockpitSelection`）。统计截至当前时间。「经营总览」和「广告与线索」两个分区内切换标签时保留所选时间段。销售业绩页按自然月选择（个人目标按月设置），同样截至当前时间。

## 定义

| 指标 | 规则 |
| --- | --- |
| 新增询盘 | 询盘日期在时间段内（没有询盘日期时按建档日期）的客户，包括待分配和管理员名下的客户，每位客户只计一次；不含回收站 |
| 有效客户 | 新增询盘中，没有被判为无效，并且标记为有效（已回复到确认采购的阶段由系统自动标记，2026-10-15 起），或者已经推进到报价、跟进、确认采购、成交阶段 |
| 成交额、毛利、成交笔数 | 成交日期在时间段内的成交，不含回收站客户；不同币种分开统计，不换算 |
| 订单 | 下单日期在时间段内、未取消的订单，不含回收站客户 |
| 报价 | 已发送的报价，按发送日期；草稿不算 |
| 报价额 | 上述报价的金额：多行报价单取报价总额（产品小计 + 运费 + 其他费用，即客户看到的金额），旧的单行报价取单价 × 数量；规则在 `lib/quotation-amount.ts`；不同币种分开统计，不换算 |
| 报价超时 | 报价发出超过 3 天，客户仍在推进中（不是成交、流失、无效、暂停），且之后没有联系记录 |
| 逾期任务 | 未完成且截止时间已过的任务，范围与任务页相同（管理员看全部，销售看自己的） |

## 话术效果（2026-10-21 起，`services/outreach-analytics-service.ts`）

| 指标 | 规则 |
| --- | --- |
| 触达 | 一组主动消息（10 分钟内连发的算一组）：破冰期记 T0–T4，沉默期记 R1–R3，对话中不算；只记录话术功能上线（`Setting.outreachStartedAt`）之后的消息 |
| 计入话术统计 | 识别出话术、按原样或轻改发出、判定已完成的触达；大幅改写、自由发挥、未登记的模板归「非标准话术」 |
| 发送数 | 上述触达条数；24 小时回复率与有效回复率的分母只算已满 24 小时（或已回复）的触达 |
| 24 小时回复率 | 发送后 24 小时内收到非「无效」回复的触达 ÷ 分母；自动回复不算，超过 24 小时的迟到回复单独计数 |
| 有效回复率 | 24 小时内回复为「高意向」或「有效互动」的触达 ÷ 分母 |
| 回复归属 | 破冰（或唤醒）期间客户的第一组有效回复，归给它之前最后发出的那条触达；之后的消息不再计入破冰统计 |
| 胜出概率 | 同一触达位置内、满 30 条的话术之间，Beta(回复数 + 1, 未回复数 + 1) 抽样 10000 次排第一的比例（固定随机种子）；≥ 90% 建议胜出，< 10% 建议停用，只是建议 |
| 按等级推荐 | A / B / C 分开算；某等级没有话术满 30 条时，用 A+B 合并数据给参考，标注「合并数据」 |
| 非标准话术占比 | 每位业务员近 7 天已判定触达中非标准话术的比例，超过 30% 提醒 |
| DeepSeek 改判率 | 本月被人工改过的 AI 判定记录 ÷ 本月 AI 判定的触达与回复；不含语音、图片的人工判定，超过 15% 提示校准提示词 |

所有门槛都是 `Setting.outreachConfig` 里的参数（话术库页面的「统计与判定参数」），为空时用 `lib/outreach.ts` 的默认值。

## 每日复盘（2026-10-22 起，`services/daily-review-service.ts`、`lib/workbench.ts`）

只统计本人的复盘，其他人看不到。

| 指标 | 口径 |
| --- | --- |
| 三件事完成率 | 当天三件事里完成的件数 ÷ 三件事件数。计入已提交复盘的日子和系统记下的没复盘日子（按当天勾选）；**周末照常计入**；标为休息的日子、草稿、没有三件事的日子不计入。没有可计入的日子显示 `—` |
| 本周完成率（工作台首页） | 本周周一到昨天的上述口径，加上今天（今天提交复盘后才计入） |
| 昨天完成 | 昨天的复盘或系统记录里的 完成 / 件数；昨天休息时显示「昨天休息」 |
| 连续复盘 | 到今天为止连续提交复盘的天数。休息日不打断也不增加；没复盘（系统记下或草稿没提交）中断；什么记录都没有的一天允许 1 天（不定期单休），连续 2 天中断。今天没提交前不影响 |
| 平均每天顺延 | 当月计入完成率的日子里，顺延到第二天的件数 ÷ 天数 |
| 改进做到率 | 复盘时回答「上次的改进做到了吗」选「做到了」的次数 ÷ 回答次数；「部分」单独列出，不计入做到 |
| 精力分配（记录页） | 当月完成的事项（按完成时间）按 转化 / 前端 / 数据 分类占比，对照 60 / 20 / 20 |
| 当天的数据（复盘存档） | 新线索：询盘日期在当天（没有询盘日期按创建时间）；平均首回：这些线索从创建到第一次联系（首联 / 联系 / 主动消息中最早的）的分钟数平均；客户回复：当天判定的客户回复组数，高意向为 `HIGH`；发出报价：当天发送的报价单数（本周为周一至当天）。提交时存进复盘，之后不再变化 |

## 客户雷达 · 开发信效果（2026-10-28 起，`services/radar-analytics-service.ts`）

页面「客户雷达 · 开发信效果」`/radar/stats`，只有管理员能看。按公司时区的自然周（周一 00:00 起）统计，显示最近 8 周；没有数据的格子显示 `—`。

| 指标 | 规则 |
| --- | --- |
| 新增 A、B 级 | 本周入库的雷达客户里评为 A、B 级的家数 |
| 有效邮箱率 | 上述客户里至少有一个邮箱验证为有效或风险、并且没退过信的比例 |
| 发出 | 本周发出的信（已发出 + 退信），第 1、2、3 封都算；「状态不明」不算 |
| 退信率 | 本周发出的信里退信的比例，按发出时间归周，目标 3% 以下；预热加量看的是每个发信邮箱近 7 天自己的退信率，另算 |
| 发信客户 | 本周发出第 1 封、而且这封没有退信的公司数 |
| 回复率 | 发信客户里有真人回复的比例：自动回复、退信不算；回复不论什么时候到，都归到第 1 封所在的周，所以前几周的数字会因迟到的回复变大 |
| 有效回复 | 本周收到、最终分类为要报价 / 要样品、有兴趣 / 要资料、业务提问、转介绍的回复封数 |
| 回复里的投诉 | 本周收到、AI 判为投诉的回复封数 |
| Gmail 投诉率 | Postmaster Tools 里每个发信域名的用户举报垃圾邮件比例，每天 08:00 后读一次，取最近 3 天里最新有数据的一天；≥ 0.1% 推送提醒，≥ 0.3% 暂停这个域名的全部发信邮箱。Gmail 只给发信量大的域名出数据，没有数据显示 `—` |
| 模板对比 | 同一语言、同一封次的版本放在一起；只算没被人工改过正文的信。发出 = 送达（不含退信），有回复 = 这封信收到过真人回复，有效回复率同理；胜出概率与话术效果相同（Beta 抽样），门槛是发信规则里的「最少样本」（默认 100 封），≥ 90% 建议胜出、< 10% 建议停用，只是建议 |
| 进入 BOS 之后 | 有效回复推进到客户库的客户数（每位客户计一次，不含回收站）；其中有报价时间，或处于已报价、跟进中、确认采购、已成交阶段的家数 |
| AI 判断准确率 | 本周（周一起）抽查里「判对了」÷ 抽查条数。抽查样本是近 7 天 AI 判断过的回复，判为有效、无效的各最多 10 条，没抽查过的排在前面；低于 90% 时提示调整提示词 |
| 近 4 周人工复核 | 近 28 天在「待复核 · 回复」里确认、改判的条数 |
| 回复分类 | 近 28 天收到的回复按最终分类计数 |
| 每日小结（推送） | 每天 08:00 后推送一次前一天（公司时区）的数字：新入库家数、发出封数、回复封数（按分类）、退信封数、队列里还没发的封数（准备中、待审核、排队中） |

## 各页面

- **经营驾驶舱**：成交额、报价额、毛利、订单、新增客户、漏斗（线索 → 有效客户 → 已报价 → 谈判中 → 成交）都按上表。
- **来源与国家**：新增询盘和有效客户按询盘日期；成交客户与成交额按成交日期，客户按其来源和国家归类。合计与驾驶舱相同。
- **财务**：收入、产品成本、毛利与订单数按上表，跟随所选时间段。
- **销售业绩**：顶部「本月新增询盘」「本月成交笔数」是全公司合计（与驾驶舱一致）；表格按销售分行，最后一行「待分配 / 管理员名下」是没有分给销售的部分，各行相加等于合计。
- **广告效果**：只统计能追溯到广告的客户（按留资日期），有效客户用同一条规则；订单按成交日期。它回答「广告带来了什么」，所以数字小于全公司合计是正常的。
- **任务页**：「逾期」和驾驶舱「任务已逾期」用同一条规则；「报价超过 3 天未推进」建议与驾驶舱用同一条规则。
