# 指标口径

同一个数字在不同页面必须一样。驾驶舱、来源与国家、财务、客户分析、销售业绩、广告效果、任务页都从 `lib/metrics.ts` 取同一套规则；页面上显示的说明文字在 `lib/metric-notes.ts`。改口径时只改这两个文件，并跑 `tests/metrics-consistency.test.ts`（它在同一时间段比较各页面的数字，必须相等）。

## 时间段

分析页面共用一个时间选择：今天、本周、本月、本季度、本年、自定义（参数 `range`、`startDate`、`endDate`，解析在 `cockpitSelection`）。统计截至当前时间。「经营总览」和「广告与线索」两个分区内切换标签时保留所选时间段。销售业绩页按自然月选择（个人目标按月设置），同样截至当前时间。

## 定义

| 指标 | 规则 |
| --- | --- |
| 新增询盘 | 询盘日期在时间段内（没有询盘日期时按建档日期）的客户，包括待分配和管理员名下的客户，每位客户只计一次；不含回收站 |
| 有效客户 | 新增询盘中，没有被判为无效，并且标记为有效（已回复到确认采购的阶段由系统自动标记，2026-10-15 起），或者已经推进到报价、跟进、确认采购、成交阶段 |
| 已回复（系统自动） | 客户在**我们发出第一条消息之后**回复（2026-10-29 起，`lib/metrics.ts` `repliedAfterContact`）。广告自动带出的消息、客户在我们开口前发来的消息都不算回复：阶段不变、不标有效、不向 Meta 回传 LeadQualified。客户回复后被判「拒绝」仍算有效，确实无效时由业务员改为「无效客户」 |
| 成交额、毛利、成交笔数 | 成交日期在时间段内的成交，不含回收站客户；不同币种分开统计，不换算 |
| 订单 | 下单日期在时间段内、未取消的订单，不含回收站客户 |
| 报价 | 已发送的报价，按发送日期；草稿不算 |
| 报价额 | 上述报价的金额：多行报价单取报价总额（产品小计 + 运费 + 其他费用，即客户看到的金额），旧的单行报价取单价 × 数量；规则在 `lib/quotation-amount.ts`；不同币种分开统计，不换算 |
| 报价超时 | 报价发出超过 3 天，客户仍在推进中（不是成交、流失、无效、暂停），且之后没有联系记录 |
| 逾期任务 | 未完成且截止时间已过的任务，范围与任务页相同（管理员看全部，销售看自己的） |

### 有效口径调整（2026-10-29）

此前任何一条客户消息都会让系统把客户改为「已回复」并标为有效，包括点广告进 WhatsApp 时自动带出的那句话。调整后：

1. 新消息按上表的「已回复」规则判断；历史导入不论先到哪条，结果相同。
2. 部署时 `scripts/production-init.mjs` 运行 `prisma/requalify-replies.ts`（也可手动 `pnpm db:requalify-replies`）：只找**系统自己设的**「已回复」客户，若客户的消息都在我们第一条之前，改回「已联系」（我们发过消息）或「新线索」，有效性改回待判断，并写一条阶段历史（备注「有效口径调整」）。人工改过的阶段、已推进到后续阶段的客户、真正回复过的客户都不动。还没发给 Meta 的 LeadQualified 取消（改名为 `…:revoked`，以后真正回复时重新回传）；已经发出的无法撤回，只在日志里计数。可重复运行，第二次起不再改动。
3. 因此 2026-10-29 之前时间段的「有效客户」「有效率」会比原来低，这是口径更正，不是数据丢失。

## 新客户与旧客户（2026-10-29 起，`lib/customer-group.ts`）

询盘日期（没有询盘日期按建档时间）早于 2026-10-01 00:00（北京时间）的是**旧客户**，其余是**新客户**。话术效果、人工复核、每日复盘的「客户回复」，以及今日工作、待首联、待处理（手动标记除外）、跟进队列、待分配提醒这些工作清单只算新客户；驾驶舱、来源与国家、财务、销售业绩、广告效果、看板、订单与报价不区分，新旧客户都算。详见 [话术效果分析与工作日历](OUTREACH_AND_WORKBENCH.md#12-新客户--旧客户分开2026-10-29)。

## 话术效果（2026-10-21 起，`services/outreach-analytics-service.ts`）

| 指标 | 规则 |
| --- | --- |
| 触达 | 一组主动消息（10 分钟内连发的算一组）：破冰期记 T0–T4，沉默期记 R1–R3，对话中不算；我方还没发过消息时客户先来消息，我方第一条仍记 T0（2026-10-29 起）；只记录话术功能上线（`Setting.outreachStartedAt`）之后的消息；只算新客户（旧客户以前的记录保留，不计入） |
| 计入话术统计 | 识别出话术、按原样或轻改发出、判定已完成的触达；大幅改写、自由发挥、未登记的模板归「非标准话术」。话术库里删除的话术，它发出的触达不计入任何数字，也不算非标准话术 |
| 发送数 | 上述触达条数；24 小时回复率与有效回复率的分母只算已满 24 小时（或已回复）的触达 |

| 有效回复率 | 24 小时内回复为「高意向」或「有效互动」的触达 ÷ 分母 |
| 回复归属 | 破冰（或唤醒）期间客户的第一组有效回复，归给它之前最后发出的那条触达；之后的消息不再计入破冰统计 |
| 胜出概率 | 同一触达位置内、满 30 条的话术之间，Beta(回复数 + 1, 未回复数 + 1) 抽样 10000 次排第一的比例（固定随机种子）；≥ 90% 建议胜出，< 10% 建议停用，只是建议 |
| 按等级推荐 | A / B / C 分开算；某等级没有话术满 30 条时，用 A+B 合并数据给参考，标注「合并数据」 |

| DeepSeek 改判率 | 本月被人工改过的 AI 判定记录 ÷ 本月 AI 判定的触达与回复；不含语音、图片的人工判定，超过 15% 提示校准提示词 |

所有门槛都是 `Setting.outreachConfig` 里的参数（话术库页面的「统计与判定参数」），为空时用 `lib/outreach.ts` 的默认值。

## 客户分析（2026-10-31 起只看有效客户，`services/customer-analytics-service.ts`、`lib/analytics.ts`）

统计对象是**询盘日期在时间段内的线索**（同「新增询盘」），比上期 = 紧挨着的同样长的一段时间。**只有「新增线索」是全部线索**；其余数字、图表和名单都只看 **有效客户 = A / B 级，并且在我们发出第一条消息后客户回复了**（`lib/analytics.ts` `isEffective`：等级 A / B 且符合上表「有效客户」）。C、D 和未评级的客户回复了也不算。可按负责人、来源、国家筛选；等级只能选 A + B（默认）、只看 A、只看 B，等级不影响「新增线索」。

| 指标 | 规则 |
| --- | --- |
| 新增线索 · 全部 | 全部线索数，并按 A / B / C / D / 未评级 分开计数 |
| A / B 线索 | 等级 A 或 B 的线索；占比的分母是新增线索 |
| 有效客户 · 有效率 | A / B 里符合「有效客户」的；有效率 = 有效客户 ÷ A / B 线索（以前是 ÷ 新增线索） |
| 已报价 · 成交 | 有效客户里到过「已报价」「成交」的人数（按到过的最远一步，后来流失的也算）；成交率 = 成交 ÷ 有效客户。成交日期可以在时间段之后 |
| 新增线索的去向 | 有效客户 / A / B 还没回复 / 其余等级 / 未评级，四段加起来 = 新增线索 |
| A / B 首联按时率 | 规则不变：A、B 线索里有首联期限的，首次联系不晚于期限的 ÷（按时 + 超时） |
| 在等我们回复 | 有效客户里最后一条客户消息比我们最后一条消息晚的人数；超过 2 小时单独计数 |
| 联系了还没回复 | A / B 里我们联系过（发过消息、记过跟进或完成首联）但还不是有效客户的；超过 2 天 = 首次联系已超过 2 天 |
| 每天 | 按询盘日期，每天的 A 有效、B 有效、A / B 还没回复；底下是当天的广告花费 |
| 走到哪一步 | 有效客户到过的最远一步：已回复 → 需求确认 → 已报价 → 成交 |
| 来源、国家、负责人 | A / B 线索按来源、国家、负责人分组：A / B 数、有效数、有效率、成交数；按有效客户数排，来源和国家取前 5，其余合成一行 |
| 广告效果 | 花费、展示、点击、平台线索来自 Meta 广告同步（`MarketingMetric`，按广告系列按天，广告账户币种），按同步日期落在时间段内；客户按第一条留资或点广告发消息的归因（`CustomerLeadAttribution`）归到广告系列 / 广告组 / 广告素材。每个 A / B 线索 = 花费 ÷ A / B 线索；每个有效客户 = 花费 ÷ 有效客户；每个成交 = 花费 ÷ 成交。Meta 只同步到广告系列的花费，所以广告组、素材只看转化。广告部分不受负责人、来源、国家筛选（花费分不出这些）；不同币种的花费只显示主要币种并注明 |

## 消息分析（2026-10-31 起只看有效客户，`services/message-analytics-service.ts`、`lib/analytics.ts`）

统计对象是**和有效客户（A / B 且回复了，同客户分析）的 WhatsApp 消息**，按发送时间落在时间段内，不含发送失败和待发送的消息；同一方在话术参数「分组分钟数」（默认 10 分钟）内连发的算一组，与话术效果相同。客户的自动回复（话术引擎判为「无效」的回复组）不算客户消息。负责人、等级（A + B / 只看 A / 只看 B）、国家筛选的是客户；发送方式（BOS 模板 / BOS 文字 / 手机）只筛选我们发出的消息。客户回复率、回复质量、模板消息不再显示（只看回复过的客户时没有意义）。

| 指标 | 规则 |
| --- | --- |
| 有效客户发来 · 我们发出 | 时间段内的消息组数，以及涉及的客户数；比上期按同样长的上一段 |
| 回复速度 | 客户一轮消息（我们回复前连发的几组算一轮）的第一组，到我们下一组消息的分钟数，取中位数；超过一天没回算「超过 24 小时或没回」，不到一天还没回的暂不计入。小图是每天的中位数 |
| 在等我们回复 | 当前时刻，正在跟进的有效客户（不含已成交、流失、无效、暂不需要）里，最后一条客户消息比我们最后一条消息晚的；按等得最久的排，超过 2 小时单独计数 |
| 聊天现在怎样 | 同一批客户分三类：等我们回复 / 等客户回复（最后一条是我们，且 3 天内有消息）/ 3 天没动静（双方都超过 3 天没消息） |
| 发消息的时间 | 有效客户的消息组按星期 × 小时计数，可切换公司时区或客户当地时间（`lib/country-timezone.ts`；没有对应时区的国家不计入并注明） |
| 负责人 | 按客户负责人：有效客户数、收到 / 发出的组数、回复中位数、在等回复的人数 |

## 进线时间（2026-11-02 起，`lib/entry-time.ts`、`services/entry-time-service.ts`）

- **进线时间** = 线索第一次进入系统的时刻，就是 `Customer.inquiryAt`：广告表单用 Meta 的提交时间（不是同步进系统的时间），点广告发 WhatsApp / 直接发 WhatsApp 用客户第一条消息到达的时间，手动录入当天的记录录入时刻、选了之前日期的只有日期。
- **准确钟点**：公司时区的 00:00:00.000 视为「只有日期」（手动选日期、表格导入没有时间），按小时的分析（热力图、工作时间内 / 外）不算它；没有 `inquiryAt` 的老记录用录入时间代替，标「估算」。
- **工作时间**：`Setting.workStartHour` / `workEndHour`，按公司时区的整点，默认 8:00–22:00，在 AI 计划页改。进线时间不在这段里就是「工作时间外进线」。
- **客户当地时间**：按客户国家的时区（`lib/country-timezone.ts`，多时区国家取人口最多的那个），冬夏令时由时区库处理；国家不明时只显示公司时间。
- 同一客户再次留资，进线时间保留第一次；之后的留资在「从进线到现在」里显示为「再次进线」。
- 客户列表「进线时间」列和「工作时间外 / 内」筛选、客户预览和档案里的「从进线到现在」（进线 → 评级 → 第一条消息等了多久 → 已读 → 回复 → 报价 → 成交 / 流失）都用这一套。

## 需求画像（2026-11-02 起，`lib/demand-profile.ts`、`services/demand-profile-service.ts`）

- 字段：买家类型、品类、尺寸、数量、包装、目的港、要求到货、客户提到的价格、认证要求、贸易条款，每位客户每项一行（`CustomerDemandField`）。
- 来源只有客户自己的话（WhatsApp 收到的文字和表单答案）：先按规则摘，配置了 DeepSeek 再让 AI 补；AI 的每个值必须引用客户原话，尺寸、数量、价格里的数字必须出现在原话里，否则丢掉。
- 摘出来是「待确认」，人点 ✓ 或自己改过才算「已确认」；之后重新摘不会覆盖已确认和人填的值。只有已确认的进国家作战卡的「客户要什么」、报价单旁的提示和 AI 计划。
- 尺寸、数量、目的港都确认后显示「可以出报价单」；价格、起订量、交期仍然只从产品库来，客户提到的价格只做参考。
- 还缺的项（最多两项）给一句客户语言的问法，只放进输入框，不会自动发。

## 国家作战卡（2026-11-02 起，`services/country-card-service.ts`、`lib/country-card.ts`）

- 范围：选定国家（客户资料里的国家）近 4 / 8 / 12 / 26 周**按进线时间**进来的线索；成交周期、每个有效客户带来的毛利和流失原因看近 12 个月。管理员看全部，销售看自己的。
- **进线时间 × A / B 占比**：只算有准确钟点的进线；**发首条的时间 × 3 天内回复率**：每位客户我们发出的第一条，发出满 72 小时才算（避免刚发的算成没回）。格子不到 3 位不上色；可切换公司时间 / 客户当地时间，白格是工作时间外。
- **首联速度**：A / B 从进线到我们第一条消息的分钟数，分 5 分钟内 / 5–30 分钟 / 30 分钟–2 小时 / 2–10 小时 / 更久，各组的有效率。
- **跟进次数**：我们 1 小时内连发的消息算一次；客户一回复就重新数；第 N 次发出后 72 小时内客户回复（且在我们下一次之前）算回复。
- **已读**：首条的送达到已读、已读不回（已读且 72 小时没回）、已读到回复，来自 WhatsApp 回执。
- **广告**：客户按第一次归因的广告；花费来自 Meta 按国家 × 广告的每日数据（`AdDailyMetric` grain=COUNTRY），没同步时显示「—」不估算。投放时段用 Meta 按小时的花费（`AdHourlyMetric`，广告账户时区），按每条广告在这个国家的花费占比分摊到这个国家，再按客户当地时间分成 4 段。
- **自动找出的地方**：每组至少 20 位客户才比较，差距太小不写；只说相关，不说因果。
- **节假日**：固定日期和复活节推算的日期是准的；伊斯兰节日按预计日期，标「约」。

## AI 计划（2026-11-02 起，`services/ai-plan-service.ts`、`lib/ai-plan.ts`）

- 今天的时间线：上班先处理昨晚下班后到今早进来的 A / B（按等级、等了多久排）→ 到期的跟进（约好今天的、报价发出 3 天没回音的）→ 有「回复率最高时段」的国家，它的跟进放进那个时段（来自国家作战卡近 12 周，至少 20 次首条）→ 不着急的事（待确认的需求画像、可以出报价的客户、广告建议）→ 收尾。在等我们回复的有效客户单独列在最上面。一项做完（发了消息、记了跟进）自动打勾。
- 周报：上一个完整周（周一到周日，公司时区）和再前一周比：有效客户、每个有效客户的广告花费、A / B 首联用时中位数，都按进线时间归属。
- 广告建议：按星期的 A / B 占比差（每组 ≥ 20 位、差 ≥ 15 个百分点）、工作时间外进线的有效率差（每组 ≥ 20 位、差 ≥ 10 个百分点且工作时间外进线 ≥ 30%）、素材每个有效客户的成本差（各 ≥ 3 位有效、贵的 ≥ 便宜的 1.5 倍）。同一条每周只出一次；采纳 7 天后自动复盘：这个国家采纳前 7 天和后 7 天的有效率、每个有效客户的花费。
- 系统从不自己发消息、不自己改广告；采纳只是记下决定，改动由人在 Meta 后台做。

## 各页面

- **经营驾驶舱**：成交额、报价额、毛利、订单、新增客户、漏斗（线索 → 有效客户 → 已报价 → 谈判中 → 成交）都按上表。
- **来源与国家**：新增询盘和有效客户按询盘日期；成交客户与成交额按成交日期，客户按其来源和国家归类。合计与驾驶舱相同。
- **客户分析**：新增线索与驾驶舱、来源与国家相同；**有效客户只算 A / B**，所以比驾驶舱、来源与国家的有效客户少（那里 C 级回复了也算）；已报价、成交只算有效客户、按到过的最远一步。
- **消息分析**：只看和有效客户的聊天，按消息时间，不按询盘日期，所以客户数与新增线索不是同一批人。
- **财务**：收入、产品成本、毛利与订单数按上表，跟随所选时间段。
- **销售业绩**：顶部「本月新增询盘」「本月成交笔数」是全公司合计（与驾驶舱一致）；表格按销售分行，最后一行「待分配 / 管理员名下」是没有分给销售的部分，各行相加等于合计。
- **广告效果**：只统计能追溯到广告的客户（按留资日期），有效客户用同一条规则；订单按成交日期。它回答「广告带来了什么」，所以数字小于全公司合计是正常的。
- **任务页**：「逾期」和驾驶舱「任务已逾期」用同一条规则；「报价超过 3 天未推进」建议与驾驶舱用同一条规则。
